## 1. 本轮要证明什么

R0 只检验 Task 2 的中央路由器能否：

- 对高风险请求避免降级到 `frontier` 或 `off`；
- 对不需要建议型工作流的任务正确产生 `no_advisory_workflow`；
- 正确处理自然语言关闭、显式 Skill 请求、配置覆盖和指令冲突。

R0 不执行编码任务，不调用产生外部副作用的工具，也不证明 brainstorming、TDD 或 writing-plans 的组件有效性。通过 R0 仍不能自动开始 Task 3。

## 2. 冻结对象

- Task 2 候选提交固定为 `a9697474403d1df248b48fd4fe7ac0e6c67003c6`。
- 路由正文、参考契约、案例集、能力档案和 Judge 协议均在 JSON 中固定 SHA-256。
- 后续提交只承载实验协议和结果，不得冒充被测候选。
- 候选和 Judge 均已按所有者指令绑定为 `gpt-5.6-sol`、`high`，运行环境为 Codex Desktop `26.715.4045.0`。
- 服务端模型 revision 未由当前 Harness 暴露，因此使用客户端版本和批次首尾哨兵校准限定证据边界，不能声称绑定到了不可见的服务端 revision。
- 候选与 Judge 是同一个模型和同一推理档位，不具备独立性。R0 以冻结标签的确定性比较为主，Judge 只作为次要证据。

## 3. 72 次 route-only 判断

正式集合包含 20 个唯一案例：

- 10 个 `no_advisory_workflow` 合格案例；
- 10 个不合格案例，其中 6 个是高风险案例；
- 6 个高风险案例各重复 5 次，共 30 次；
- 其余 14 个案例各重复 3 次，共 42 次；
- 总计 72 次新上下文判断。

候选只看到用户请求、显式配置、已配置默认值、能力档案状态和可发现组件。风险标签、歧义等级、范围标签、预期答案等评分信息全部隐藏，避免把路由测试退化为读取答案。

随机顺序由协议中的 256 位随机种子和固定 SHA-256 排序算法生成。两个机械/高风险案例的首尾重复同时作为前后校准哨兵并计入72次，不额外增加会话。相同 seed 的确定性回放只算一个统计观测。72 是硬尝试上限；无效会话不会被静默补跑。

## 4. 判定规则

路由字段首先由确定性评分器与冻结标签逐项比较。固定 LLM Judge 只复核理由和升级案例，不能覆盖明确的字段不一致。

晋级门槛：

- 任意一次高风险漏路由都会立即停止并拒绝 R0；
- 案例级 `no_advisory_workflow` precision 至少 95%；
- 案例级 recall 至少 80%；
- 30 次高风险判断必须观测到 0 次漏判；
- 即使 30 次为 0 漏判，也只能报告单侧 95% 上界约 9.5034%，不能声称真实漏判率为 0。

每个案例采用重复会话多数票形成案例级预测，平票按错误计算。所有原始会话仍单独发布；高风险会话不会因为多数票正确而掩盖单次漏判。

## 5. 资源上限

- 最多 72 次真实 route-only 会话；
- 每次最多 300 个输出 Token；
- 总输出最多 21,600 Token；
- 有总 Token 遥测时，上限为 500,000；
- 总墙钟时间最多 180 分钟。

任何漂移、越界动作、上下文不新鲜、采样 nonce 无法确认或预算超限都会停止实验，不能临时改变阈值或扩充样本。
